# XDGAME 抓取流程完善设计草案

> 状态：最终验收前补充 `export` 子命令，正在实施  
> 创建日期：2026-10-17  
> 适用目录：`xdgame/`

## 1. 背景

现有脚本能够抓取首页“今日更新”、读取详情页并通过 Playwright 补充夸克地址；当前工作区还新增了使用环境变量自动填写账号密码的登录流程。Bugbot 对这批改动发现 5 个问题，其中图片验证码回退可能一直等待 `cap_token` 是阻断提交的问题。

本需求在修复当前改动后，继续把一次性脚本演进为可持久化、可断点续跑、可分批补全、可日常调度并能记录和通知异常的本地抓取任务。

## 2. 目标

1. 修复 Bugbot 报告的 5 个问题，复审通过后再提交自动登录改动。
2. 使用 SQLite 持久化游戏、抓取状态和运行记录，并在首次运行时自动初始化。
3. 抓取“电脑游戏”分类的全量列表，避免只依赖首页“今日更新”。
4. 支持列表抓取与详情补全的断点续跑。
5. 分批获取详情信息和夸克地址，控制访问频率和单次任务规模。
6. 支持日常增量更新，只处理新增或需要重新检查的记录。
7. 配置 Windows 定时任务执行日常更新。
8. 增加结构化运行日志和登录失效通知。

## 3. 非目标与边界

- 不绕过图片验证码、智能验证、会员权限或其他访问控制；需要人工验证时明确提示并安全退出或等待人工操作。
- 不抓取用户无权访问的内容，不提高并发来追求速度。
- 保留单一命令行入口，业务实现集中到顶层 `xdgame_scraper/` 导入包并按数据库、抓取和登录职责拆分；当前本地 CLI 暂不采用需要安装步骤的 `src/` 布局。
- 本需求不新增或修改自动化测试代码，不创建 `tests/` 内容，也不执行测试脚本；验证计划仅记录在 `test.md`，由人工执行。
- 不把账号密码、Cookie、登录状态、时效性网盘地址、数据库、输出 JSON 或日志提交到 Git。

## 4. 当前现状

- 仓库根目录为 `scrapers/`，目标项目位于 `xdgame/`。
- `scraper.py` 目前包含 HTTP 会话、首页解析、详情解析、Playwright 回退、登录状态保存、JSON 输出和 CLI。
- 自动登录使用 `XDGAME_USERNAME`、`XDGAME_PASSWORD` 环境变量；缺少环境变量时保留手动登录方式。
- 当前默认输出为源码目录下的 `today_games.json`，该文件已经被 Git 跟踪。
- `requirements.txt` 仅列出依赖名，没有版本约束。
- HTTP 和浏览器详情循环没有主动请求间隔。
- 项目未发现额外的 `AGENTS.md`、`CLAUDE.md` 或 `docs/` 编码规范，评审以对话中提供的项目规范为准。

## 5. 总体方案

### 5.1 提交前修复

#### 图片验证码与智能验证

登录流程按页面实际存在的控件区分处理：

- 存在普通原生勾选框：自动勾选后提交。
- 存在 `cap_token`：提示用户完成人机验证，仅在该字段确实存在时等待其产生有效值。
- 不存在 `cap_token` 或验证控件无法识别：进入明确的人工登录回退，不再等待一个不存在的字段。
- 登录成功不能只依赖单一 DOM 节点消失；实现时应结合登录表单消失、页面跳转或已登录标识，选择当前站点可稳定观察的条件。

Playwright 的超时异常统一转换为简短、可操作的中文 `RuntimeError`，避免正常失败直接打印完整堆栈。浏览器和上下文通过 `try/finally` 或上下文管理保证关闭，成功与异常路径都不遗留进程。

#### 请求节流

HTTP 详情循环和 Playwright 详情循环共享可配置的随机间隔策略，每次访问不同详情页前后按确定的规则等待。间隔通过配置对象传递，不给函数增加超过 3 个位置参数。默认区间确认为 2～4 秒；重试退避继续由现有 `Retry` 负责。

#### 依赖与运行产物

- 将直接依赖固定为经过本机验证的明确版本；Playwright 浏览器仍通过 `python -m playwright install chromium` 安装与该版本匹配的 Chromium。
- 新增并忽略 `data/`、`output/`、`logs/`。
- 默认 JSON 输出迁移到 `output/today_games.json`。
- 已跟踪的 `today_games.json` 从版本库移除；如需保留本地历史数据，实施前先迁移到 `output/`。
- `login_state.json` 保持忽略；根目录与子目录中仅为 `.niko` 添加的重复忽略规则可在实施时整理，但不得使 `.niko` 失去忽略保护。

### 5.2 SQLite 数据库与自动初始化

默认数据库建议为 `data/xdgame.db`，连接时创建父目录，并使用 `PRAGMA user_version` 管理结构版本。初始化操作必须幂等，已有数据库只执行必要迁移，不清空数据。

建议数据模型：

- `games`：游戏唯一标识、名称、详情页 URL、分类、首次/最近发现时间、详情状态、夸克地址及状态、尝试次数、最后错误、详情更新时间。
- `crawl_checkpoints`：任务类型、列表游标或页码、最后处理的游戏、更新时间，用于断点续跑。
- `crawl_runs`：运行模式、开始/结束时间、状态、处理数量、错误摘要，用于日志关联和运行追踪。

详情页 URL 作为天然唯一键进行 UPSERT，避免重复记录。时间统一存储带时区的 ISO 8601 字符串。

### 5.3 电脑游戏分类全量列表

实现独立的列表页解析和分页推进逻辑：

1. 从配置的电脑游戏分类入口开始。
2. 解析当前页的名称、详情 URL、分类和可用的列表元数据。
3. 按详情 URL 批量 UPSERT 到 `games`。
4. 每成功落库一页后更新 checkpoint。
5. 根据站点实际分页结构继续，直到没有下一页或达到人工配置的安全上限。

分类 URL、分页参数和稳定选择器需在实施阶段基于实际页面只读确认，不能在文档中臆造。若页面结构变化，应给出清晰错误并保留已落库进度。

### 5.4 断点续跑

- checkpoint 只在一页或一批数据成功提交后前移，数据库事务失败时不更新。
- 再次运行默认读取同一任务的未完成 checkpoint；提供显式“从头扫描”能力，但全量重扫仍依赖 UPSERT，不产生重复记录。
- 详情补全按稳定顺序读取状态为待处理或可重试的记录，每处理完一条立即持久化结果；进程中断后从剩余记录继续。
- 连续失败需要记录尝试次数和最后错误，达到上限后标记为失败，避免每次运行无限重试；上限需人工确认。

阶段划分：第四阶段先完成全量列表分页 checkpoint 与任务互斥；详情逐条状态、尝试次数和失败恢复随第五阶段 `enrich` 一并实现，避免在详情抓取能力存在前创建无法验证的半成品流程。

### 5.5 详情和夸克地址分批补充

- 处理范围包括 `full-list` 写入的全部待处理游戏，不得只补充首页“今日更新”记录。
- 通过批量大小限制单次任务数量，默认 20 条，单条最大尝试 3 次。
- 优先使用 HTTP 获取公开内容；仅对未解析出地址的记录使用带登录状态的 Playwright。
- HTTP 和浏览器请求均应用随机间隔。
- 登录失效、无权限、找不到按钮、页面结构变化和临时网络失败使用不同状态，便于决定是否重试。
- 保存夸克地址时更新获取时间；已成功获取的地址默认每 30 天复查一次。

### 5.6 日常增量更新

日常模式先扫描站点最新列表，将新记录和已有记录的列表元数据及 `last_seen_at` 更新到数据库，再分批补充新增、待处理、可重试或到期复查的记录。

增量列表默认最多扫描 10 页；连续 3 个完整页面没有发现新游戏时提前停止。`--max-pages` 和 `--existing-page-limit` 分别允许覆盖最大页数及连续无新增页数。提前停止前已经扫描到的已有记录仍正常执行 UPSERT，不因“没有新增”跳过元数据更新。如果达到最大页数时最后一段仍持续出现新游戏，则本次运行记录为 `incomplete` 并返回非零退出码，提示人工扩大页数后再次运行；已成功扫描的页面不会回滚。

该策略以网站列表大体按更新时间倒序排列为前提，通过连续 3 页缓冲降低单页重排造成漏抓的风险；最大 10 页同时限制每日请求量。若站点排序规律变化，需要人工扩大参数或重新执行全量列表扫描。

### 5.7 Windows 定时任务

在代码和人工验证完成后，用 Windows 任务计划程序创建日常任务：

- 工作目录固定为 `xdgame/`，使用明确的 Python 可执行文件和脚本绝对路径。
- 任务执行日常增量模式，输出进入日志，不依赖交互式终端。
- 使用保存好的登录状态，不把账号密码写入任务参数。
- 配置失败重试、最长运行时间和“错过计划后尽快运行”。

创建外部系统任务前需确认执行时间、Python 路径和运行账户；这些信息不在当前文档中猜测。

第七阶段人工输入与本机检测结果：每日 `23:00` 执行；Python 为 `E:\Python\Python314\python.exe`（3.14.6）；当前 Windows 账户为 `AyouWorkPC\xiejinjian`；同名任务“XDGAME 每日增量更新”当前不存在。运行账户尚需确认采用“仅用户登录时运行”，还是由用户在任务计划程序中亲自输入密码以支持“无论是否登录都运行”。密码不得写入文档、脚本或聊天。

### 5.8 日志与登录失效通知

- 使用标准 `logging` 同时输出控制台和轮转文件 `logs/xdgame.log`；单文件 5 MiB，保留 5 份历史文件。
- 每次运行生成 12 位运行标识，记录阶段、数量、耗时、重试和摘要；不得记录账号密码、Cookie 或完整登录状态。
- 检测到登录页、状态文件无法加载或需要重新登录时，写入明确日志并统一以退出码 `3` 结束；普通失败使用 `1`，命令行参数错误保留 `argparse` 的 `2`，用户中断使用 `130`。
- 按人工确认不接入 Windows 通知或 Webhook；Windows 计划任务通过非零退出码触发既有失败重试。

### 5.9 SQLite JSON 导出

- 新增 `export` 子命令，只读加载现有 SQLite `games` 表，不发起网络请求、不修改游戏或抓取状态。
- 默认写入 `output/games.json`，通过现有 `--output` 参数覆盖；`today` 的默认输出仍为 `output/today_games.json`。
- 导出包含 `games` 表的全部业务字段，并附带导出时间、记录数、已完成详情数和已取得夸克地址数。
- 数据库不存在时明确失败，不自动创建空数据库；输出目录保持 Git 忽略。

## 6. CLI 与兼容性

脚本需要逐步支持登录、全量列表、详情补全、日常增量和导出等运行模式。具体采用子命令还是模式参数待确认。无论选择哪种形式：

- 现有 `--login`、`--login-state`、`--show-browser` 的迁移方式必须写入 README。
- 路径默认值相对于脚本目录或显式工作目录解析，避免定时任务从其他目录启动时写错位置。
- 公开函数继续遵守最多 3 个参数的强制规范，相关选项通过配置对象封装。
- 函数体、嵌套和圈复杂度继续保持在项目阈值内。

## 7. 风险与缓解

- 站点结构变化：解析器集中维护选择器，结构不匹配时立即失败并保留 checkpoint。
- 限流和账号风控：串行处理、随机等待、有限重试、分批运行，不提高并发。
- 登录状态泄露：状态文件、数据库、日志和输出目录全部忽略提交；日志脱敏。
- 数据库损坏：小批量事务提交；修改结构前备份由人工操作，迁移通过版本号控制。
- 定时任务重复执行：启动时使用数据库锁或进程锁，检测已有运行则安全退出。
- 夸克地址失效：保存获取时间和状态，允许后续按策略重新检查。

## 8. 回滚方案

- 每个阶段单独提交，后续阶段出现问题时可以回退对应提交。
- SQLite 引入前保留 JSON 导出能力；数据库异常时停止写入，不覆盖已有数据库。
- Windows 定时任务可以禁用或删除，不影响手动运行。
- 登录自动化失败时继续保留人工登录路径。
